### 2. 模型结构(每条链路方向)

- **发端**:每 bit 一个总量(串化器、驱动器、其模拟 FIR);有 DAC(`tx.dac_bits`)时加数字 FIR,每抽头一次加法
  (符号 × 权重是查表),发端 PR 把 FIR 加长 `len(target) − 1` 抽头。
- **收端共用**(两种架构同一个系数,比较时抵消):CTLE / VGA 前端、时钟与 CDR,每 bit 一个总量。
- **混合信号专有**:时钟比较器 = 数据比较器 (N − 1)(tap1 展开时 × N)+ DFE 自适应的误差比较器 1 + bang-bang CDR 的边沿比较器 1;
  模拟 DFE 每抽头每符号一份(展开的 tap1 不进求和点)。
- **ADC 专有**:ADC 按 Walden(P = FOM·2^ENOB·fs,每 bit ×2)或 Schreier(每 bit ×4);`enob` 未设时按 `n_bits` 计价并在备注里写明。
  FFE = 抽头数 × 乘法(ADC 位宽 × `numeric.ffe_weight.wl`)+ 累加;数字 DFE 的 tap1 按投机展开(N 个候选各自判决)。
- **序列检测**(两种架构都可挂):Viterbi 状态数 N^(len(pr.target) − 1 + mlsd.memory) —— 与引擎 `_mlsd_post_detect` 的网格一致;
  每符号 = 每个光标一次乘法(y·c_i 共享)+ 每分支 3 次加法(分支度量 2、加比选 1)+ 每状态 N − 1 次比较,位宽 `metric_bits` = 12。
  滑动检测器:3 个假设 × 窗长。
- **光路**(`topology.optical` 非 none):E/O + O/E 每 bit 一个总量,按 `topology.optics_placement` 取可插拔模块(`pluggable`,默认)
  或共封装光引擎(`co_packaged`)的那个;两者之差代表模块自身的开销(电源转换与管理、驱动器 / TIA 跨主机板上走线)。
  这个字段只有功耗模型读,引擎只认段 A / B 的损耗(2026-10-12)。**重定时**(`retimer: both`):模块两端各一对收发,按同样规则从
  `retimer_rx` / `retimer_tx` 计价,× 2。
- **数字能耗只算运算**:流水线寄存器、时钟树、100 GBd 所需的并行展开、LMS 更新、Viterbi 幸存路径存储都不算 —— 数字块是下限,
  `digital_overhead` 统一乘一个系数做敏感度。

### 5. 结论(示例 41;"成立"指在第 5 节全部系数变体下方向不变)

- **ADC 收端 vs 混合信号收端**(示例 07 的两个收端):1.60 vs 4.81 pJ/b,3.01×,其中 ADC 一块 3.17 pJ/b;tap1 展开的混合信号
  2.00 pJ/b(比较器 ×4)。各变体下(示例 41 第 5 节)2.01–5.85×,**成立**:ADC 收端总是更贵,差的大头是 ADC。
- **ADC 分辨率是最不确定的一项**:ENOB 6.5 → 7.5 在 Walden 下 +3.17 pJ/b,Schreier 146 dB 下 +23.12、151 dB 下 +7.31 ——
  定律选哪个,结论差一个数量级。更要紧的是:调查表里 ≥ 40 GS/s 的最高 ENOB 是 6.67(72 GS/s),≥ 100 GS/s 是 6.22(105 GS/s,698 mW);
  示例 19 / 21 的 ENOB 6.5 @ 112 GS/s 已在前沿,**ENOB 7.5 @ 112 GS/s 没有任何已发表器件**,+8.2 dB 的 ADC 杠杆的代价是外推(2026-10-13 ADC 收端的 DFE 起作用后重测,此前 +5.4 dB)。
- **PR 目标长度:每多一个受控光标 Viterbi ×3.76 / ×3.91**(16 → 64 → 256 状态;乘法那部分只加一次,所以略小于 4)。
  第一个光标(示例 36,+5.0 dB)+2.39 pJ/b;第二个(示例 38,再 +2.3 dB)+9.48 pJ/b;三光标 memory 1 与两光标同为 256 状态、
  同价;memory 2 的 1024 状态 Viterbi 一块 50.56 pJ/b。两者同为数字块,比值不随数字系数变,**成立**。
  256 状态在默认系数下 12.73 pJ/b,只算运算就远超已发表 224G 收端的总量 1.41 pJ/b —— 全网格的第二个受控光标在 112 GBd 上
  不现实,要做只能是降状态检测。(2026-10-11 同日更新:降状态网格已建,`rx.mlsd.state_memory`,模型按 N^K 状态加逐路径反馈计价;
  示例 42 量到两光标目标 16 状态拿到与 256 状态相同的 38.60 dB,Viterbi 估计 1.02 pJ/b,见 `DSP发端与PR.md` §18。原句"本模型不建"作废。)
- **"DSP 深度"与收端 PR 打平**(2026-10-13 更正):同样从 16 到 64 状态,示例 19 的 DFE8 + memory 3 花 +2.17 pJ/b 换 +4.7 dB,

  量的是 +1.8 dB,那时 ADC 收端的 DFE 从不起作用(ROADMAP P1 #21),作废。
- **ENOB +1 与第一个 PR 光标谁更省:不确定**。默认 +3.17 vs +2.39;FOM 38 fJ 时 +1.72 vs +2.39、数字 ×3 时 +3.17 vs +7.17,
  方向随系数翻转。
- **LPO / CPO / retimed**(示例 33 的链路,每链路方向):LPO 13.25、retimed 21.76 pJ/b(重定时器 8.51);各变体下 retimed / LPO
  1.53–1.75,**成立**。
- **CPO 比 LPO 省 22%,成立;大头是模块自身开销**(2026-10-12,原"同价"一句见更正段)。同样的收端(ENOB 5.5、17 抽头):CPO 11.15
  对 LPO 13.25,差的 2.10 就是光路系数之差。再问"短走线让主机收端省多少":示例 41 在 100 m OM4 上对两条链路各跑时域 ENOB 阶梯
  (0.5 bit 一档,9 抽头 LMS FFE,CTLE 6 / 7.5 / 9 dB 取最好,ADC 满量程 0.2),pre-FEC 不超过 KP4 门限的最低 ENOB:**LPO 5.0**
  (CTLE 9 dB,1.68e-4;4.5 时最好也 5.93e-4)、**CPO 3.5**(CTLE 7.5 dB,1.06e-4;3.0 时 1.00e-3)。按各自收端计价:LPO 12.57、
  CPO 9.74 pJ/b,共省 2.82 —— 模块开销 2.10,1.5 bit ADC 0.72。系数各变体下 CPO / LPO 0.67–0.86,两端由 CPO 光引擎系数
  (5.6 / 8.0)决定;ADC 系数只动 0.75–0.80。

### 6. 不建的部分

- 速率依赖:FOM、比较器、共用块都按每 bit / 每符号常数;真实设计在高速端 FOM 变差、共用块每 bit 变省。
- 数字开销:寄存器、时钟树、并行展开、LMS、幸存路径存储(`digital_overhead` 只做敏感度)。
- M 算法等其他降复杂度检测(降状态 DFSE 2026-10-11 已建)、FEC 编解码器、CDR 环路的数字部分(进共用块)、TI-ADC 校准、激光器 / TEC 单列。
- 光路器件按种类(VCSEL / EML)的差别:一个总量。CPO 与 LPO 只差在光路总量(可插拔 / 共封装两个系数)和收端配置(由仿真定);
  发端驱动随摆幅、走线省下的那部分不建(`tx_j_per_bit` 与摆幅无关);外置激光源单列与否,资料没说。

## 坑

- **比两种拓扑要各调各的 CTLE 与 ADC 满量程,否则差距被放大**。沿用示例 33 的收端(CTLE 3 dB、满量程 0.3,9 抽头)时 100 m 处
  LPO 要 ENOB 6.5(6.0 时 2.76e-4),CPO 到 4.5 仍过(1.13e-4,更低没量),至少差 2 bit;两边各自调好后是 5.0 对 3.5,差 1.5 bit。
  满量程 0.15 削顶(BER 5e-3–4e-2),0.3 / 0.4 浪费量程
  (LPO ENOB 5.5、9 抽头、CTLE 3 dB:0.2 → 2.3e-4,0.3 → 1.3e-3,0.4 → 5.1e-3);CTLE 9 dB 放在 CPO 的 4 dB 段上过峰,
  ENOB 再高也停在 1.4e-4 —— 只给一个 CTLE 档,阶梯会在擦边处停(ENOB 3.5、CTLE 9 dB:2.11e-4,门限 2.19e-4),加 7.5 dB 一档后是 1.06e-4。
- **`enob` 未设(理想量化器)按 `n_bits` 计价**:示例 32 / 33 的 10 bit 理想 ADC 直接计价会得到 ENOB 10 的功耗(2^10 × FOM × fs),
  毫无意义;示例 41 把它们按 ENOB 5.5 重新计价并写明。报告的备注里有 "(enob unset: n_bits)"。
- **DeepScaleTool 的 `Energy` 宏只认 130 / 90 / 65 / 45 / 40 / 32 / 28 / 22 / 14 / 10 / 7 nm**,其他输入(比如 5)落到 `Else`
  分支按 7 nm 算,不报错。
- **检索摘要里 Horowitz 的"16 位加 0.18 / 乘 0.62 pJ"与 32 位加 0.1 pJ 自相矛盾**(16 位加法比 32 位还贵),出处是另一篇论文 / 另一口径,
  未采用;8 位的 0.03 / 0.2 pJ 是记忆值,没核实,也未采用(位宽缩放从 32 位推出 0.025 / 0.19,与之同量级)。
