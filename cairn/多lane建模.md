### 4. 共享 CDR / lane 间 skew 预算

- 静态部分(一个 CDR 的相位给 N 条 lane 用,lane 间有固定 skew)等于每条 lane 在偏离自己最佳相位 skew 处的 BER —— 统计引擎已经报 BER 随相位
  (浴盆),读出来就是 skew 预算,不需要改引擎。
- 动态部分(主 lane 的 CDR 跟踪抖动,从 lane 带 skew 跟着走;lane 间相关抖动)要多 lane 同时跑的时域内核,是另一个量级,按需。
- **更正(2026-10-13,做 9c 时)**:"读浴盆、不需要改引擎"只对一半。lane 的 DFE、判决电平、(ADC)FFE 在它采样的地方重新适应,
  所以曲线是"每个偏移处均衡器重解后的 BER":混合信号的浴盆本来就是(每个相位按该相位的游标放 DFE 与电平);ADC 的浴盆不是
  (FFE 沿用锁定点的那个,偏 1/4 UI 读高 21×),而且均衡后的脉冲最大样本可能不是主光标,一次运行的浴盆在偏移处会认错主光标。
  所以加了 `run_statistical(phase_ui=)`(引擎改了一个参数)。见 §8。

### 6. FEC 映射与交织(P3 #9a,2026-10-13 已做)

**做法**(`fec/interleave.py`,示例 43):时域引擎的 extras 增加 `reference`(与 `decisions` 同长,−1 是周跳留下的空位;只加键,
指纹不动)。`bit_errors` 按 Gray 比特(MSB 在前)给出误码的线上比特位置;`FecLayout(lanes, pcs_lanes, mux_bits, interleave, stagger)`
把物理 lane 上的比特映射到 (码字, RS 符号):一个物理 lane 承载 `pcs_lanes` 条 FEC lane、按 `mux_bits` 比特一组复用(1 = 比特复用,
10 = 按符号,20 = 符号对);FEC 符号轮流分给各 FEC lane,FEC lane q 上第 s 个符号属于本组的第 (s + stagger·q) mod interleave 个码字。
误码按间隔 ≤ 8 个符号分事件,每个"事件 × 码字"记它占了几个符号(足迹);帧错误率 = 复合泊松尾部:每个码字被事件碰到的次数
~ Poisson(λ),λ = 碰到次数 × n·10 / 比特数(各物理 lane 统计相同且独立时,只需一条 lane),每次贡献实测足迹分布,P(Σ > t)
按尾部直接求和(1e-13 量级,不能用 1 − P(≤ t))。等效门限 = FER 等于二项投影在其门限 P* = 2.19e-4 处 FER 的那个 pre-FEC BER
(事件率随 BER 线性缩放、足迹不变)。

**校验**:合成的突发误码(4 条 lane 都生成,按全局 FEC lane 映射后逐码字直接数)对复合泊松 P(> t),t = 0…5,各映射在蒙特卡洛
误差内吻合(只用一条 lane 估 λ 时散布大到尾部差 10 %,所以单测把多条 lane 的事件合起来估);相互独立的比特误码在 P* 处
等效门限 0.95–0.99(泊松对二项的 1.4 % 加上偶然相邻的两个误码被当成一个事件,方法本身略偏悲观);相隔很远的单个误码
正好 0.986。事件间隔取 2 / 4 / 8 / 16 个符号,PR 链路的门限比不动(误码串里没有空隙),DFE 链路变 ≤ 0.08。

  "PR 买多少 dB"要说清是哪种 FEC 映射、DFE 是否真在用。(2026-10-13 更正:原写"DFE 的误码基本孤立,映射几乎不影响它(−0.25…+0.02 dB)、
  1 + aD 对 DFE1 在 3.09–5.55 dB(二项 4.98)",是 DFE 抽头停在 0 时量的,ROADMAP P1 #21。)
- **8:1 比特复用对 PR 是灾难性的**(等效门限 0.05–0.07 倍,−2.1…−2.2 dB):一串误码的每个比特各进一个 RS 符号,0.129 的"事件 × 码字"
  占 3 个以上。这与 802.3df 资料里"相关误码下 8:1 比特复用不可接受、改用符号对复用"的结论同向(二手)。
- **预编码**把 1 + aD 的一串误码变成恰好两个(2.64 → 2.00 / 事件),按 Gray 比特数 BER 反而略低(0.24 m:2.52e-4 → 2.01e-4,
  二项 reach +0.19 dB);它只在比特复用下有用(8:1:+1.63 dB),在符号对复用下略亏(−0.11 dB)。DFE 上同样:预编码把一串误码压成
  约两个(3.05 → 1.92 / 事件),BER 也低(1.81e-4 → 1.19e-4),二项 reach +0.49 dB、4:1 比特复用 +0.78 dB、符号对 −0.01 dB。
  (2026-10-13 更正:DFE 抽头停在 0 时误码孤立,预编码把每个变成两个,4:1 比特复用 −1.24 dB、符号对 −0.08 dB。)
- 这些门限比是在门限附近(BER 1.2–2.5e-4)量的;读 reach 时用在别的 BER(比特复用 8:1 要读到 1e-5 附近)假设了足迹不随 SNR 变。
  单 lane 的门限比 bootstrap 区间最宽(1 + aD + bD² 0.35–0.61):少数占 3–4 个符号的事件决定尾部。
- 映射是二手资料的模型(棋盘 stagger、符号对的"奇数 lane 延后两个码字"按 (s + 2q) mod 4 近似,只在长于 M·g = 160 比特的突发上与
  真实结构不同),各物理 lane 统计相同且互不相关(串扰造成的跨 lane 相关误码不在内)。
- 顺带发现:`symbol_checker` 把 Gray 下只差一比特的 0 ↔ 3 记成 2 bit,预编码 PAM4 的 BER 因此高 25 %(ROADMAP P2 #20;
  2026-10-13 已修,两个引擎都按 Gray 码不同的比特数计)。

### 7. 准同步 lane 与串扰入配置(P3 #9b,2026-10-13 已做)

**配置**:`LinkConfig.crosstalk`(`CrosstalkConfig`)= 一组合成 lane(`n_fext` / `n_next`、`coupling_db` ± `spread_db`、`seed`,即
`aggressor_bank`)+ 逐个列出的 `aggressors`(`AggressorConfig`:合成,或 `file` 从多端口 Touchstone 的两个口之间取耦合)。
bank 的 lane 共用 `skew_ui` / `ppm`;列出的各自给;列出的 lane 不给 `seed` 时接在 bank 之后,两条 lane 不会共用数据。
时域(含流式)、统计、COM 都从这里建 aggressor;显式 `xtalk=` / `xtalk_pulses=` 替换配置(两者都有时警告)。静态引擎遇到配置串扰报错
(它不注入串扰),带重定时器的拓扑也报错(三条链路,一个串扰环境说不清属于哪段)。表单(桌面 / Android)有 bank 那七项,
`aggressors` 只在 YAML。没有串扰时指纹 846 值逐位不变。

**准同步**:`ppm` ≠ 0 的 lane 有自己的参考时钟。时域:它的第 k 个符号在受扰采样点 n 上,k = floor(n (1 + ppm·1e-6) / osr)
(`crosstalk.symbol_index`,默认引擎与流式引擎同一个函数),相位每 UI 走 ppm·1e-6 UI。统计:受扰轮流在 aggressor 脉冲的每个相位上采样、
每个相位一样多 —— 该 aggressor 的 ISI PDF 取各相位的平均(与受扰自己的相位无关,算一次;PR 联合界的事件投影同样按相位平均)。
一个 aggressor 时这正是同步各 skew 的 BER 的平均(PDF 尾部对它线性;单测逐位到 1e-6)。前提:一次运行扫过整 UI ——
`n_symbols × |ppm| × 1e-6` < 1 时统计引擎警告。

**量**(示例 44:2 FEXT + 2 NEXT,30 万符号;统计 / 时域):

|---|---|---|---|---|---|
| 224G ADC 106 GBd,1.5 mV,−46 dB | 4.66e-4 … 1.32e-2(28.4×) | 0.86–1.15 | 3.00e-3 / 2.91e-3 | 0.72 / 0.74 | 0.87 / 0.85 |
| PAM4 32G 混合信号,6 mV,−34 dB | 8.64e-4 … 7.69e-3(8.9×) | 0.85–1.23 | 2.62e-3 / 2.57e-3 | 0.84 / 0.86 | 0.96 / 0.94 |
| NRZ 28G,10 mV,−27 dB | 9.15e-4 … 2.95e-2(32.2×) | 0.41–1.17 | 8.22e-3 / 8.25e-3 | 0.80 / 0.79 | 0.97 / 0.97 |

- 224G ADC 一行是 2026-10-13 P1 #21 之后重量的(ADC 的 DFE 起作用、统计引擎计 DFE 误码传播);之前是 2.13e-3 … 3.46e-2(16.3×)、
  0.98–1.02、8.08e-3 / 7.81e-3、0.90 / 0.93、0.83 / 0.80。另两行不变。
- 准同步的统计结果与 ppm 的大小无关(探针:+100 / −100 / +300 ppm 逐位相同),时域 ±100 / +300 ppm 在计数误差内一致。
- 同步 lane 的串扰代价随 skew 差一个数量级;准同步 lane 落在各 skew 的平均附近 —— 同步 lane 的 skew 是可以设计的量,准同步给的是平均。
- NRZ 在 7/8 UI 的 0.41 是 §3 那一点(浴盆在锁定点旁太陡),不是串扰模型的问题。
- 测试:`tests/test_crosstalk.py` 配置与 API 逐位相同、YAML 往返、校验、相位平均 = 各 skew 平均、两组链路准同步铁律 3、流式、静态 / 重定时报错、COM 从配置取。

### 8. 共享 CDR 的静态 skew 预算(P3 #9c 静态部分,2026-10-13 已做)

**做法**(`analysis/skew.py`,示例 45):一个 CDR 的时钟采 N 条 lane,数据晚到 s UI 的 lane 被早采 s UI,即偏离它自己环路的锁定点 −s。
lane 的其他环路仍在它采样的地方适应 —— DFE 抽头、判决电平、ADC 的 FFE —— 所以要的是**均衡器在每个偏移处重解后**的 BER 曲线:
`lane_curve` 每个偏移跑一次统计引擎,`run_statistical(phase_ui=d)` 在锁定点 + d 处采样,相位轴以那里为中心(主光标就是那里采到的,
和 PR 目标时的做法一样;`None` 时走原路径,指纹不动;`phase_ui = 0` 与原 `ber` 逐位相同,混合信号上各偏移与原浴盆插值差 1e-14)。
ADC 收端要给 `ffe_taps`:一组(每个偏移同一个),或采样相位 → FFE 的函数。`LaneCurve` 给读数(对数线性、过半 UI 回绕 —— 那时采的是
下一个符号,deskew 重排)、最低点、`window(BER 目标)` 与宽度 `budget_ui`;`shared_cdr(curves, skews, policy)` 按 master(一条 lane 的环路带全部)、
average(一个环路听所有 lane,线性区锁在 skew 的圆周平均)、minmax(最差 lane 最小,即逐 lane 眼扫描校准)放时钟,给各 lane 的 BER。

**8.1 时域对照的做法**:时域 lane 用冻结的环路(`kp_shift = ki_shift = 60`)加常数接收时钟偏移停在锁定点 + d,**并且**判决电平、DFE、
FFE 从那里的游标起步(测试里 monkeypatch `timedomain.rx_clock_offsets_samples` 与 `timedomain.channel_cursors`,`tests/test_skew.py`)。
不这样做读到的是"没适应的接收机":引擎从脉冲峰值处的游标起步,混合信号的判决电平根本不适应、sign-sign LMS 一次运行挪不动 DFE ——
PAM4 32G 在 −3/8 UI 读 1.5e-1,从该相位起步是 1.7e-4。
