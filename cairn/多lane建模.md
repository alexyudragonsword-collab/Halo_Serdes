### 2. 探针一:误码成簇,以及它对 KP4 的影响

- **PR 目标 + Viterbi 的误码天生成串**(1 + aD:99 % 的事件跨多个符号,平均 3.2 个)。在连续映射下一个事件多半只落进 1–2 个 RS 符号,
  RS 符号误码率只有二项投影的 0.46 倍 —— 也就是说,示例 36 / 38 / 42 这类按 BER 做 KP4 投影的 reach 在单 lane 连续映射下**偏悲观**。

  比值是方向性的。

> 第一条"DFE 链路几乎不成簇,二项投影就是对的"也要收窄:21 抽头 FFE + DFE1 的误码 1.07 个 / 事件,在单 lane 与比特复用下等效门限

### 3. 探针二:串扰相位(lane 间 skew)

`aggressor_bank` 的 4 个 aggressor(FEXT / NEXT 各半),把每个耦合冲激整体延后 0…7/8 UI(等于同步 lane 间的固定 skew),时域 30 万符号;
统计引擎用同一组 `aggressor.pulse()`:

| 链路 | 无串扰 时域 / 统计 | 时域 BER,aggressor 延后 0 / 1/8 / … / 7/8 UI | 统计(带串扰) | 统计 / 时域 |
|---|---|---|---|---|
| PAM4 32G 混合信号,4 × −30 dB,噪声 6 mV | 0 / 7.6e-7 | 3.13e-2 7.39e-3 6.71e-3 6.81e-3 8.18e-3 1.11e-2 1.68e-2 2.56e-2 | 3.81e-2 | 1.2–5.7× |
| NRZ 28G analytic,4 × −27 dB,噪声 10 mV | 0 / 9.9e-16 | 9.15e-4 1.14e-3 1.76e-3 3.22e-3 7.75e-3 1.81e-2 2.95e-2 5.59e-3 | 3.76e-2 | 1.3–41× |

- 串扰代价随 aggressor 相位变 4.7×(PAM4)/ 32×(NRZ):lane 间 skew 是串扰的一个一阶参数。
- **统计引擎取的是每个 aggressor 自己的峰值相位**(`statistical.py`:`xpk = argmax |pulse|`,按它取游标),等于每个 aggressor 同时处在最坏相位;
  时域则是耦合冲激碰巧对齐到哪就是哪(延后 0 只是 `synthetic_aggressor` 的构造,不是物理 skew)。两者在串扰下的比值随 skew 从 1.2× 到 41×,
  **铁律 3 在串扰下没被覆盖**:`tests/test_crosstalk.py` 只检查两个引擎都变差,不检查比值;`statistical.py` 顶部的近似清单里串扰一条
  ("独立平稳干扰")也没写"取峰值相位"。
- 准同步 lane(各自参考时钟、有 ppm 频偏)的 aggressor 相位会扫过一个 UI,物理上对应相位平均,两个引擎都没有这种模式。

**修(2026-10-13,P2 #19)**:统计引擎改在受扰 lane 的采样网格上读 aggressor —— 每个相位 φ 取耦合脉冲上下标 ≡ (峰值 + φ) mod osr 的全部游标
(aggressor 数据与受扰无关,哪个算"第 0 个"无所谓;小于最大值 1e-4 的丢掉);ADC 收端先过 FFE(时域在 ADC 之前叠加串扰,
所以串扰跟着信号一起被 FFE 放大 —— 原先统计引擎漏了这一步)。`XtalkAggressor.skew_s`(≥ 0,秒,取最近的采样点)是 aggressor 比受扰晚多久发,

### 4. 共享 CDR / lane 间 skew 预算

- 静态部分(一个 CDR 的相位给 N 条 lane 用,lane 间有固定 skew)等于每条 lane 在偏离自己最佳相位 skew 处的 BER —— 统计引擎已经报 BER 随相位
  (浴盆),读出来就是 skew 预算,不需要改引擎。
- 动态部分(主 lane 的 CDR 跟踪抖动,从 lane 带 skew 跟着走;lane 间相关抖动)要多 lane 同时跑的时域内核,是另一个量级,按需。

### 5. 拆分与顺序(写进 ROADMAP)

1. **P2 #19 串扰下双引擎口径不一致**(一致性,先做):两个引擎用同一个、显式的 aggressor 相位(同步 lane 给 skew;统计引擎按它取游标
   而不是峰值),补铁律 3 在串扰下的测试,把口径写进 `statistical.py` 的近似清单。证据见 §3。
2. **P3 #9a FEC 映射与交织**:误码位置(各 lane 的 `error_idx`)→ 按复用方式(单 lane 连续 / N lane 符号对复用 / 比特复用)与码字交织(1 / 2 / 4)
   映射到 FEC 符号 → 每码字的 FEC 符号误码分布 → FER(按事件率 × 实测事件足迹外推)。不改引擎;用它回头读示例 36 / 38 / 42 的
   PR reach 在 802.3 映射下是否偏悲观。证据见 §2。
3. **P3 #9b 准同步 lane 与串扰入配置**:频偏(时域按 ppm 重采样、统计引擎按相位平均),aggressor 环境进 `LinkConfig`(铁律 1)。依赖 #19。
4. **P3 #9c 共享 CDR**:先做静态 skew 预算(读浴盆);动态的多 lane 环路按需。

PCS 层的 deskew、对齐标记锁定、lane 重排是数字协议行为,留在「边界 — 有意不做」。

### 6. FEC 映射与交织(P3 #9a,2026-10-13 已做)

**做法**(`fec/interleave.py`,示例 43):时域引擎的 extras 增加 `reference`(与 `decisions` 同长,−1 是周跳留下的空位;只加键,
指纹不动)。`bit_errors` 按 Gray 比特(MSB 在前)给出误码的线上比特位置;`FecLayout(lanes, pcs_lanes, mux_bits, interleave, stagger)`
把物理 lane 上的比特映射到 (码字, RS 符号):一个物理 lane 承载 `pcs_lanes` 条 FEC lane、按 `mux_bits` 比特一组复用(1 = 比特复用,
10 = 按符号,20 = 符号对);FEC 符号轮流分给各 FEC lane,FEC lane q 上第 s 个符号属于本组的第 (s + stagger·q) mod interleave 个码字。
误码按间隔 ≤ 8 个符号分事件,每个"事件 × 码字"记它占了几个符号(足迹);帧错误率 = 复合泊松尾部:每个码字被事件碰到的次数
~ Poisson(λ),λ = 碰到次数 × n·10 / 比特数(各物理 lane 统计相同且独立时,只需一条 lane),每次贡献实测足迹分布,P(Σ > t)
按尾部直接求和(1e-13 量级,不能用 1 − P(≤ t))。等效门限 = FER 等于二项投影在其门限 P* = 2.19e-4 处 FER 的那个 pre-FEC BER
(事件率随 BER 线性缩放、足迹不变)。

**校验**:合成的突发误码(4 条 lane 都生成,按全局 FEC lane 映射后逐码字直接数)对复合泊松 P(> t),t = 0…5,各映射在蒙特卡洛
误差内吻合(只用一条 lane 估 λ 时散布大到尾部差 10 %,所以单测把多条 lane 的事件合起来估);相互独立的比特误码在 P* 处
等效门限 0.95–0.99(泊松对二项的 1.4 % 加上偶然相邻的两个误码被当成一个事件,方法本身略偏悲观);相隔很远的单个误码
正好 0.986。事件间隔取 2 / 4 / 8 / 16 个符号,PR 链路的门限比不动(误码串里没有空隙),DFE 链路变 ≤ 0.08。

**结果**(示例 43:示例 42 的 224G 链路,每个收端在门限附近 400 万符号;映射 = 单 lane / 4:1 比特复用两码字棋盘
(仿 400GBASE-R)/ 8:1 比特复用两码字 / 8:1 符号对复用四码字(仿 200G/lane);括号里是按事件 bootstrap 的 90 %):

| 收端 | BER | 误码 / 事件 | 单 lane | 比特复用 4:1 | 比特复用 8:1 | 符号对 4 码字 |
|---|---|---|---|---|---|---|
| FFE + DFE1 | 1.44e-4 | 1.07 | 0.84 | 0.72 | 0.66 | 1.03 |
| FFE + DFE1,预编码 | 2.80e-4 | 2.00 | 0.60 | 0.28 | 0.29 | 1.62 |
| 1 + aD,Viterbi | 2.52e-4 | 2.64 | 0.55(0.50–0.59) | 0.25 | 0.05 | 1.92(1.85–1.97) |
| 1 + aD,Viterbi,预编码 | 2.01e-4 | 2.00 | 0.31 | 0.54 | 0.31 | 1.30 |
| 1 + aD + bD²,Viterbi | 2.34e-4 | 2.33 | 0.47(0.35–0.61) | 0.26 | 0.07 | 1.80(1.75–1.86) |

二项列与示例 42 逐位相同(36.33 / 38.60 dB)。

- **回答 #9a 的问题**:示例 36 / 38 / 42 按二项投影读的 PR reach,在仿 200G/lane 的符号对复用 + 四码字下**偏保守约 0.6 dB**
  (一串误码留在一两个 RS 符号里,四码字交织又把这一两个分给不同码字,每个码字几乎只吃一个);在单 lane 连续映射与比特复用下
  **偏乐观** 0.3–2.2 dB。DFE 的误码基本孤立,映射几乎不影响它(−0.25…+0.02 dB)。所以 PR 目标相对 DFE 的 reach 优势随映射变:
  1 + aD 对 DFE1 在 3.09–5.55 dB 之间(二项投影读 4.98 dB;示例 43 末尾打印各映射下的差),"PR 买多少 dB"要说清是哪种 FEC 映射。
- **8:1 比特复用对 PR 是灾难性的**(等效门限 0.05–0.07 倍,−2.1…−2.2 dB):一串误码的每个比特各进一个 RS 符号,0.129 的"事件 × 码字"
  占 3 个以上。这与 802.3df 资料里"相关误码下 8:1 比特复用不可接受、改用符号对复用"的结论同向(二手)。
- **预编码**把 1 + aD 的一串误码变成恰好两个(2.64 → 2.00 / 事件),按 Gray 比特数 BER 反而略低(0.24 m:2.52e-4 → 2.01e-4,
  二项 reach +0.19 dB);它只在比特复用下有用(8:1:+1.63 dB),在符号对复用下略亏(−0.11 dB)。在误码本来孤立的 DFE 上,
  预编码把每个误码变成两个:符号对复用下几乎不亏(−0.08 dB),其余映射都亏(比特复用 4:1:−1.24 dB)。
- 这些门限比是在门限附近(BER 1.4–2.8e-4)量的;读 reach 时用在别的 BER(比特复用 8:1 要读到 1e-5 附近)假设了足迹不随 SNR 变。
  单 lane 的门限比 bootstrap 区间最宽(1 + aD + bD² 0.35–0.61):少数占 3–4 个符号的事件决定尾部。
- 映射是二手资料的模型(棋盘 stagger、符号对的"奇数 lane 延后两个码字"按 (s + 2q) mod 4 近似,只在长于 M·g = 160 比特的突发上与
  真实结构不同),各物理 lane 统计相同且互不相关(串扰造成的跨 lane 相关误码不在内)。
- 顺带发现:`symbol_checker` 把 Gray 下只差一比特的 0 ↔ 3 记成 2 bit,预编码 PAM4 的 BER 因此高 25 %(ROADMAP P2 #20)。
